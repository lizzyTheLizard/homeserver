# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

pnpm workspace with four packages under `services/`; target one with `pnpm --filter @homeserver/<web|assistant|whatsapp|wichteln> <script>`.

```bash
pnpm dev                 # web (:3000) + assistant (:8500) + whatsapp bridge + wichteln (:3001) as local processes
pnpm dev:wichteln        # wichteln alone
pnpm build               # build all packages
pnpm test                # all tests, all packages
pnpm lint                # eslint --fix in all packages (pnpm lint:ci = no fix, used in CI)
pnpm --filter @homeserver/web vitest run path/to/file.tests.ts   # single test file
pnpm --filter @homeserver/web vitest run --project unit          # single vitest project
pnpm --filter @homeserver/web storybook                          # Storybook on :6006
```

Development happens inside the `dev-machine` container (repo at `/home/dev/workspace`, dev Postgres already running — no local docker compose needed). All dev scripts load `services/.env`; Wichteln reads unprefixed `SESSION_SECRET`/`ADMIN_USER`/`ADMIN_PASSWORD` there (in prod they come from `WICHTELN_*` via docker-compose). Playwright OS deps are preinstalled there but browser binaries are not: before running the `storybook` test project, run `pnpm exec playwright install --with-deps` from the repo root if Chromium is missing.

## Development workflow (OpenSpec)

All changes are spec-driven and change-first via [OpenSpec](https://github.com/Fission-AI/OpenSpec). There is no GitHub issue in the flow; the change name, branch name and `openspec/changes/<change>` folder are the same kebab-case slug.

`openspec-explore` → `openspec-propose` (creates branch `<change>` from `origin/main`, writes proposal/specs/design/tasks, commits) → `openspec-apply-change` (one task at a time: implement → user reviews diff → commit → push) → `openspec-archive-change` (archive commit, PR, auto-merge, watch CI).

The binding rules (branch invariants, commit trailers `OpenSpec-Change:` / `Agent:`, PR format, no issue numbers) live in `openspec/config.yaml` and are injected into those workflows; inspect them with `openspec instructions proposal|apply|archive --change <name> --json`. The `openspec-*` skills in `.claude/skills/` are generated by the OpenSpec CLI — never edit them by hand. Main specs in `openspec/specs/` mirror the repo structure.

## Architecture

Services (each its own container image in GHCR, built/deployed by its own workflow in `.github/workflows/`, run on a self-hosted home server via `infrastructure/docker-compose.yml`):

- **`services/web`** — Next.js App Router portal (apps: `cash`, `coeditor`, `admin`, `startpage`; shared layer in `app/shared/`). React Server Components by default, `"use client"` only for interactivity. Mutations are Server Actions in a `server.ts` next to each `page.tsx` — no separate API layer.
- **`services/assistant`** — standalone service on port 8500. Serves the assistant WebSocket (proxied by nginx) and internal REST APIs `/microsoft/*` and `/whatsapp/*` that the web app calls via `ASSISTANT_INTERNAL_URL` (not exposed publicly). Owns Microsoft tokens, mail/todo/calendar workers, WhatsApp proxying, weather/geolocation and background sync, talking directly to the shared Postgres.
- **`services/whatsapp`** — bridge container: the prebuilt [wacli](https://github.com/openclaw/wacli) binary plus an Express companion (`companion/`) that drives it and exposes REST. One wacli process per user (`auth --events` while unpaired, `sync --follow --events` while paired); reads are one-shot `wacli --json` calls; `archive-chat`/`mark-chat-read`/`full-sync` briefly pause sync to take the store lock. Per-user SQLite stores live in `WHATSAPP_DATA_DIR` (Docker volume, deliberately not backed up). No Go code in the repo.
- **`services/wichteln`** — separate Next.js app (port 3001 in dev) sharing the Postgres DB with `wichteln_*`-prefixed tables.
- **`services/dev-machine`** — development container (code-server, Claude Code Remote Control, Storybook, SSH on 2222).

**Auth** — `services/web/proxy.ts` runs before every route and validates the iron-session cookie; unauthenticated users are redirected to Azure AD OIDC via `startLogin()` in `app/shared/auth/auth.ts`, AJAX requests get 401. `/shared/auth/*`, `/shared/ping`, static assets and Next.js internals bypass auth. The assistant validates the same cookie on its WebSocket. Row ownership is keyed on the user's email (`owner_email`, from the OIDC claim); there is no users table.

**Database** — PostgreSQL via `pg`. The pool is created lazily on first use by `app/shared/_external/db/setup.ts`, which also runs the migrations from `services/web/db/` at that point (assistant and wichteln have their own `db/` migration folders). All access goes through `app/shared/_external/db/access.ts`: `transactional(fn)` (BEGIN/COMMIT/ROLLBACK) or `nontransactional(fn)`. Custom type parsers (`TYPE_MAPPINGS`) keep dates as strings and turn numerics into JS numbers.

**Ops** — the `backup` service dumps the prod DB nightly and uploads to OneDrive; restore with `docker compose exec backup node /usr/local/bin/restore-backup.mjs <file> <dev|prod> [--yes]` (use `--yes` for prod, since exec has no TTY). Details in `infrastructure/README.md`.

## Tests (web)

Vitest runs three projects (`services/web/vitest.config.mts`):

- `unit` — `**/*.tests.ts` excluding `server.tests.ts`
- `integration` — every `server.ts` has a `server.tests.ts` that runs against in-memory PGlite seeded with all migrations from `services/web/db/`
- `storybook` — Story interaction tests in headless Chromium via Playwright

## Conventions

- Non-route folders in `app/` are prefixed with `_` (`_components/`, `_data/`, `_external/`, `_helper/`).
- CSS only in `*.module.css` files beside the component; no inline styles.
- Client-only rendering is guarded with `useIsClient()` from `app/shared/_helper/useIsClient.ts`.
- One React component per file.
- Keep each `import` statement on a single line.
- Exported and test functions first in a file; internal helpers at the end.
