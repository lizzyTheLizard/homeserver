# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

pnpm workspace with three packages under `services/` (plus the dev-machine image); target one with `pnpm --filter @homeserver/<web|wichteln|backup> <script>`.

```bash
pnpm dev                 # web (:3000) + wichteln (:3001) + the backup service as local processes
pnpm dev:wichteln        # wichteln alone
pnpm dev:backup          # the backup service alone (watch mode, schedule 03:00, dev DB, never uploads)
pnpm --filter @homeserver/backup dev:now   # one backup right now outside docker (dev DB, never uploads)
pnpm build               # build all packages
pnpm test                # all tests, all packages
pnpm lint                # oxlint --fix, then oxfmt, in all packages (pnpm lint:ci = checks only, used in CI)
pnpm --filter @homeserver/web vitest run path/to/file.tests.ts   # single test file
pnpm --filter @homeserver/web vitest run --project unit          # single vitest project
pnpm --filter @homeserver/web storybook                          # Storybook on :6006
```

Development happens inside the `dev-machine` container (repo at `/home/ubuntu/workspace`, dev Postgres already running — no local docker compose needed). All dev scripts load `services/.env`; Wichteln reads unprefixed `SESSION_SECRET`/`ADMIN_USER`/`ADMIN_PASSWORD` there (in prod they come from `WICHTELN_*` via docker-compose). Playwright OS deps are preinstalled there but browser binaries are not: before running the `storybook` test project, run `pnpm exec playwright install --with-deps` from the repo root if Chromium is missing.

## Development workflow (OpenSpec)

All changes are spec-driven and change-first via [OpenSpec](https://github.com/Fission-AI/OpenSpec). There is no GitHub issue in the flow; the change name, branch name and `openspec/changes/<change>` folder are the same kebab-case slug.

`openspec-explore` → `openspec-propose` (creates branch `<change>` from `origin/main`, writes proposal/specs/design/tasks, commits) → `openspec-apply-change` (all tasks in one go → user reviews the full diff → one commit → push) → `openspec-archive-change` (sync delta specs automatically, archive commit, PR with auto-merge, follow the PR until merged; a fix for a failing check is only committed and pushed after the user reviews it).

The binding rules (branch invariants, commit trailers `OpenSpec-Change:` / `Agent:`, PR format, no issue numbers) live in `openspec/config.yaml` and are injected into those workflows; inspect them with `openspec instructions proposal|apply|archive --change <name> --json`. The `openspec-*` skills in `.claude/skills/` are generated by the OpenSpec CLI — never edit them by hand. Main specs in `openspec/specs/` mirror the repo structure.

## Architecture

Services (each its own container image in GHCR, checked by `.github/workflows/pull-request.yml` (lint, change detection, tests of the changed services, stack start, ending in the one required check "Quality Gate") and built, published and deployed by `.github/workflows/ci.yml` on every merge to `main`, run on a self-hosted home server via `infrastructure/docker-compose.yml`):

- **`services/web`** — Next.js App Router portal (apps: `cash`, `coeditor`, `admin`, `startpage`; shared layer in `app/shared/`). React Server Components by default, `"use client"` only for interactivity. Mutations are Server Actions in a `server.ts` next to each `page.tsx` — no separate API layer. The startpage also hosts the assistant: Microsoft logic (Graph, token, mail/todo/calendar workers) in `startpage/microsoft/_external/`, the WAHA client in `startpage/whatsapp/_external/`, and the chat (model, skills, tools, weather) in `startpage/assistant/`, served by the streaming `POST /startpage/assistant/chat` route handler (newline-delimited JSON; conversations live in web-process memory).
- **`services/wichteln`** — separate Next.js app (port 3001 in dev) sharing the Postgres DB with `wichteln_*`-prefixed tables.
- **`services/backup`** — nightly prod DB dump and OneDrive upload (`main.ts` schedules with `croner`, `backup.ts` runs `pg_dump`, `onedrive.ts` uploads; bundled by esbuild); its own image with the PostgreSQL client.
- **`services/dev-machine`** — development container (code-server, Claude Code Remote Control, Storybook, SSH on 2222). Remote Control runs with `--spawn worktree`: each new session gets its own git worktree under `.claude/worktrees/` with `services/.env` and `infrastructure/.env` copied in (`.worktreeinclude`); run `pnpm install` there first.

**Auth** — `services/web/proxy.ts` runs before every route and validates the iron-session cookie; unauthenticated users are redirected to Azure AD OIDC via `startLogin()` in `app/shared/auth/auth.ts`, AJAX requests get 401. `/shared/auth/*`, `/shared/ping`, static assets and Next.js internals bypass auth. Row ownership is keyed on the user's email (`owner_email`, from the OIDC claim); there is no users table.

**Database** — PostgreSQL via `pg`. The pool is created lazily on first use by `app/shared/_external/db/setup.ts`, which also runs the migrations from `services/web/db/` at that point (wichteln has its own `db/` migration folder). All access goes through `app/shared/_external/db/access.ts`: `transactional(fn)` (BEGIN/COMMIT/ROLLBACK) or `nontransactional(fn)`. Custom type parsers (`TYPE_MAPPINGS`) keep dates as strings and turn numerics into JS numbers.

**Ops** — the `backup` service dumps the prod DB nightly and uploads to OneDrive; restore by hand with `psql`/`pg_restore` inside the container. Details in `infrastructure/README.md`.

## Tests (web)

Vitest runs three projects (`services/web/vitest.config.mts`):

- `unit` — `**/*.tests.ts` excluding `server.tests.ts`
- `integration` — every `server.ts` has a `server.tests.ts` that runs against in-memory PGlite seeded with all migrations from `services/web/db/`
- `storybook` — Story interaction tests in headless Chromium via Playwright

## Conventions

- Non-route folders in `app/` are prefixed with `_` (`_components/`, `_data/`, `_external/`, `_helper/`).
- CSS only in `*.module.css` files beside the component; no inline styles.
- Client-only rendering is guarded with `useIsClient()` from `app/shared/_helper/useIsClient.ts`.
- One React component per file.
- Keep each `import` statement on a single line (oxfmt only wraps one when it exceeds 160 columns).
- Linting is Oxlint with type-aware rules (one root `.oxlintrc.json` for all packages, needs `oxlint-tsgolint`); formatting is oxfmt (one root `.oxfmtrc.json`: 2 spaces, single quotes, no semicolons, 160 columns; `pnpm lint` formats, `lint:ci` fails on unformatted files). Disable comments use `oxlint-disable-next-line <plugin>/<rule>`.
- Exported and test functions first in a file; internal helpers at the end.
