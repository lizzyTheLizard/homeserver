# Proposal

## Why

In Wichteln the administrator can reset a participant's password only from that participant's group page. Accounts are shared across groups, and an account that was removed from every group, or whose group was deleted, cannot be reached at all, so its password can never be reset. The administrator needs one place that lists every account with a reset button.

## What Changes

- New administrator page that lists every Wichteln account, including accounts that belong to no group, ordered by name. Each entry shows the account name and the names of its groups, and has a "Passwort zurücksetzen" button.
- The reset from this list behaves exactly like the existing reset: a newly generated password is shown once, the account must change it on the next sign-in, and the previous password stops working.
- The administrator overview links to the new account list.
- The existing reset button on the group page stays and resets the same account.
- The account list shows no wish contents and no passwords other than the one generated by a reset, shown once.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `wichteln`: adds a requirement for the administrator's account list with password reset, and extends the "reset password is shown only once" scenario to that list.

## Impact

- `services/wichteln/app/admin/`: new account list page, link from the overview, a reset action keyed by account.
- `services/wichteln/lib/store.ts`: query listing all accounts with their group names; password reset keyed by account instead of group participant.
- `services/wichteln/lib/store.tests.ts`: tests for the account list and the account-keyed reset.
- No database migration, no new dependency, no change to other services.
